**Use Case:** Operator views the canonical expected network state from NetBox

| **Real Runtime** | ⚠️ CONDITIONAL | Requires real NetBox instance + URL + token (environment variables) |

### Classification
**MISSING** — API gap exists

### Why It Matters
Frontend cannot directly query the expected inventory list without reconstructing it from comparison results.

### Workaround Path

### Blocker for Frontend

## API Gaps Summary

### Critical Gaps (Block Frontend Features)
1. ❌ `GET /api/v1/inventory/netbox` — List expected devices
2. ❌ `GET /api/v1/inventory/live` — List discovered devices
3. ❌ `GET /api/v1/devices/{device_id}/compare` — Side-by-side comparison
4. ❌ `GET /api/v1/devices/{device_id}/interfaces` — Interface details
5. ❌ `GET /api/v1/devices/{device_id}/vlans` — VLAN details
6. ❌ `GET /api/v1/snapshots/{snapshot_id}` — Snapshot details (for evidence tracing)
7. ❌ `GET /api/v1/history/timeline` — Unified timeline

### Nice-to-Have Improvements
- `GET /api/v1/findings?difference_type=missing` — Filter by type
- `GET /api/v1/findings?device_id=X` — Filter by device
- `GET /api/v1/jobs?status=running` — Filter jobs by status
- WebSocket `/ws/jobs/{job_id}` — Real-time progress updates

## Real Runtime Capability Assessment

### What Works With Mocks (Test Environment)
- ✅ Orchestration pipeline (full workflow passes tests)
- ✅ Comparison logic (all comparators tested)
- ✅ Persistence (data stored correctly)
- ✅ API contracts (responses match schema)

### What Requires Real Infrastructure (Production)
- ⚠️ NetBox Inventory: REQUIRES real NetBox instance
  - URL must be configured (NETBOX_URL env var)
  - Token must be valid (NETBOX_TOKEN env var)
  - NetBox API must be reachable on network
  - Version must match (4.6.7 expected)

- ⚠️ Real Discovery: REQUIRES real Cisco devices
  - Target device IP must be reachable
  - SSH/SNMP/HTTP credentials must be correct
  - Device must support the collectors (show version, show inventory, etc.)
  - Transport must be available (SSH on :22, SNMP on :161, etc.)

- ✅ Comparison & Persistence: Works with in-memory/test data
  - Does not require external services
  - Uses local PostgreSQL/SQLite
  - Full functionality proven by tests

### Gap Between Tests and Production
**Tests use fake implementations of:**
- FakeInventoryService (returns canned NetBox data)
- FakeCollectorRuntime (returns canned discovery data)
- Real implementations for comparison, persistence, APIs

**Production requires:**
- Real NetBoxClient connecting to actual NetBox API
- Real CollectorRuntimeEngine connecting to actual devices

**This is intentional and correct:**
- Unit/integration tests should not require external infrastructure
- Production must connect to real systems
- Current design allows both
