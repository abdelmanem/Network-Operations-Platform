# NetBox TLS Certificate Analysis & Remediation Plan

## Phase 1: Current Certificate State (As Reported)

### Certificate Details
- **Location**: `/etc/ssl/certs/netbox.crt` (certificate) and `/etc/ssl/private/netbox.key` (private key)
- **Type**: Self-signed
- **Subject CN**: `caizh.netbox.com`
- **Issuer CN**: `caizh.netbox.com` (self-issued)
- **Validity**: 2025-10-26 to 2026-10-26 (1 year)
- **SAN (Subject Alternative Name)**: ❌ MISSING
- **Extensions**: None reported

### Why This Fails TLS Validation
```
Python httpx/SSL validation expects:
1. ✅ Hostname matches certificate CN or SAN → CN matches but missing SAN
2. ✅ Certificate chain is valid → Self-signed, not in trust store
3. ✅ Certificate is not expired → Valid (not expired yet)

Python/httpx behavior (verify=True):
  → Checks if "caizh.netbox.com" matches certificate
  → CN="caizh.netbox.com" ✅ matches
  → But certificate NOT in OS/Python trust store → ❌ FAILS
  → SAN missing makes it technically non-compliant with modern PKI
```

### Current Problem
- Self-signed certificate without SAN causes TLS verification failure
- Even though hostname matches CN, Python's SSL validation rejects it because:
  - Self-signed certs are not trusted by default
  - Missing SAN is a compliance issue (RFC 6125)
  - No certificate chain to any trusted root

## Phase 2: Certificate Remediation Options

### Option A: Self-Signed Certificate with SAN (Controlled Internal CA)
**Safest for isolated networks. Recommended.**

**Approach:**
1. Create internal self-signed CA certificate (if one doesn't exist)
   - Store at: `/etc/ssl/private/internal-ca.key` and `/etc/ssl/certs/internal-ca.crt`
   - This CA signs server certificates
   
2. Create new NetBox server certificate signed by internal CA
   - CN: `caizh.netbox.com`
   - SAN: `DNS:caizh.netbox.com`, `DNS:192.168.137.5` (optional but recommended)
   - Signed by internal CA
   
3. Import internal CA into Network Operations Platform trust store
   - Windows: Add CA cert to local machine trust store
   - Python: Explicitly specify CA bundle in httpx
   - Docker/containers: Mount CA cert in proper location

**Advantages:**
- ✅ Proper certificate hierarchy (CA → Server)
- ✅ SAN support (modern PKI compliant)
- ✅ No verify=False needed
- ✅ Scalable (CA can sign other certs)
- ✅ Production-ready pattern

**Disadvantages:**
- Requires CA maintenance
- Must distribute CA cert to all clients

**Simpler but less scalable.**

**Approach:**

   - CN: `caizh.netbox.com`
   - SAN: `DNS:caizh.netbox.com`, `DNS:192.168.137.5`
   - Self-signed (no CA)

2. Import this certificate into Python/Windows trust store

**Advantages:**
- ✅ Simpler (no separate CA)
- ✅ SAN support
- ✅ Still allows proper TLS validation

**Disadvantages:**

**Advantages:**

## Phase 3: Recommended Path (Option A + Application Trust)

### 3.1 Certificate Generation Commands (NetBox Host)

**Step 1: Create Internal CA (if not exists)**
```bash
# On NetBox host (Linux)
cd /etc/ssl/private

# Generate CA private key (2048-bit RSA, 10 years)
openssl genrsa -out internal-ca.key 2048

# Create CA certificate
openssl req -new -x509 -days 3650 -key internal-ca.key \
  -out /etc/ssl/certs/internal-ca.crt \
  -subj "/C=US/ST=State/L=City/O=Organization/CN=Internal-CA-caizh"
```

**Step 2: Create Server Certificate Signing Request (CSR)**
```bash
# Generate server private key
openssl genrsa -out netbox.key.new 2048

# Create CSR with SAN extension
openssl req -new -key netbox.key.new \
  -out netbox.csr \
  -subj "/C=US/ST=State/L=City/O=Organization/CN=caizh.netbox.com"

# Create SAN configuration file (netbox_san.cnf)
cat > netbox_san.cnf << 'EOF'
subjectAltName = DNS:caizh.netbox.com,DNS:192.168.137.5
EOF
```

**Step 3: Sign Server Certificate with Internal CA**
```bash
# Sign CSR with CA (valid for 1 year)
openssl x509 -req -days 365 \
  -in netbox.csr \
  -CA /etc/ssl/certs/internal-ca.crt \
  -CAkey /etc/ssl/private/internal-ca.key \
  -CAcreateserial \
  -out netbox.crt.new \
  -extfile netbox_san.cnf
```

**Step 4: Verify New Certificate**
```bash
# Check certificate details
openssl x509 -in netbox.crt.new -text -noout

# Verify signature by CA
openssl verify -CAfile /etc/ssl/certs/internal-ca.crt netbox.crt.new
```

**Step 5: Deploy New Certificate**
```bash
# Backup old certificates
cp /etc/ssl/certs/netbox.crt /etc/ssl/certs/netbox.crt.backup.$(date +%s)
cp /etc/ssl/private/netbox.key /etc/ssl/private/netbox.key.backup.$(date +%s)

# Install new certificate and key
cp netbox.crt.new /etc/ssl/certs/netbox.crt
cp netbox.key.new /etc/ssl/private/netbox.key

# Set correct permissions
chmod 644 /etc/ssl/certs/netbox.crt
chmod 600 /etc/ssl/private/netbox.key

# Restart NetBox (example - actual command depends on deployment)
systemctl restart netbox
# OR for Docker:
docker restart netbox
```

## Phase 5: Application Code Changes (Post-Approval)

Once certificate is deployed and CA is trusted:

**Modified [backend/app/integrations/netbox/client.py](backend/app/integrations/netbox/client.py):**

```python
@classmethod
def from_settings(cls, settings: Settings) -> "NetBoxClient":
    """Create client from application settings."""
    token = settings.netbox_token
    normalized_base_url = settings.netbox_base_url.rstrip("/")
    
    # Build headers with token
    auth = TokenAuthentication(token=token)
    headers = auth.build_headers()
    headers.update(DEFAULT_HEADERS)
    
    # Determine CA bundle for TLS verification
    ca_bundle = settings.netbox_ca_bundle if settings.netbox_ca_bundle else True
    # If netbox_ca_bundle is empty, True uses system default trust store
    # If netbox_ca_bundle is a path, use that specific CA bundle
    
    client = httpx.AsyncClient(
        base_url=normalized_base_url,
        headers=headers,
        timeout=httpx.Timeout(settings.netbox_timeout_seconds),
        verify=ca_bundle  # TLS verification with CA bundle
    )
    return cls(client=client, settings=settings)
```
