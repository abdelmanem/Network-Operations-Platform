## Configuration Options

### Option 1: With Application-Scoped Certificate (Current)

```env
NETBOX_CA_CERT=certs/netbox.crt
```

**Behavior:**
- httpx uses the specified certificate file for TLS verification
- Certificate path is relative to application root
- Hostname validation enforced against certificate CN/SAN
- Secure and explicit

### Option 2: Without Certificate (System Default)

```env
NETBOX_CA_CERT=
# or omit entirely
```

**Behavior:**
- httpx uses system default trust store (verify=True)
- Works if NetBox certificate is signed by a trusted CA
- Falls back to standard SSL/TLS verification
- Secure default behavior

### Option 3: Absolute Path

```env
NETBOX_CA_CERT=/etc/ssl/certs/netbox.crt
```

**Behavior:**
- Works with absolute paths as well
- Useful for production deployments

## Security Analysis

### What's Secure

✅ TLS verification is **always enabled**  
✅ Hostname verification is **always enforced**  
✅ No `verify=False` in application code  
✅ No default insecure configuration  
✅ Certificate path is configurable, not hardcoded

### What's Not Used

❌ `check_hostname=False` — Hostname checking is NOT disabled  
❌ Self-signed certificate bypass — Certificate must be trusted

## How to Extend

### For Production with Enterprise CA

If NetBox certificate is signed by your enterprise CA (e.g., CAIZH-LT-ADIT), you can:

**Option 1: System trust store**
```env
NETBOX_CA_CERT=
```
The enterprise CA is already trusted on Windows (verified in inspection).

**Option 2: Explicit CA bundle**
```env
NETBOX_CA_CERT=/path/to/ca-bundle.crt
```
