# M30.1 Implementation Plan: Operator API Completion

**Objective:** Establish clean API boundary by exposing existing snapshot data and comparison results through operator-facing endpoints.

**Constraint:** Do NOT re-architect NetBox integration, discovery, comparison, or persistence.

**Validation:** All code quality checks + integration tests before M30.2.

---

## Data Flow: What Exists → What to Expose

### Current State (M29.5)

**Backend persistence (proven working):**
- `snapshots` table: NetBox expected state + live discovered state
- `snapshot_devices`, `snapshot_interfaces`, `snapshot_vlans`, `snapshot_neighbors`: Granular inventory records
- `comparison_results` + `findings`: Comparison outcome + variances
- `discovery_runs`: Job history
- Repositories query this data (SnapshotRepository, FindingRepository, HistoryRepository)

**Current API gaps:**
- No endpoint to list snapshot contents
- No endpoint to compare single device
- No endpoint to get inventory directly

### M30.1 Goal

**Expose what already exists cleanly:**
- List expected inventory (NetBox snapshot)
- List observed inventory (live snapshot)
- Get device comparison (expected + observed + variances)
- Drill into snapshot details (interfaces, VLANs, neighbors)

## API Endpoint Specification

### 1. GET /api/v1/inventory/netbox

**Purpose:** List all devices from latest NetBox snapshot (expected state)

**Request:**
```
GET /api/v1/inventory/netbox?page=1&page_size=50
```

**Response (200 OK):**
```json
{
  "source": "netbox",
  "snapshot_id": "uuid",
  "snapshot_captured_at": "2026-08-15T09:30:00Z",
  "device_count": 150,
  "items": [
    {
      "device_id": "switch-01",
      "name": "switch-01",
      "model": "Catalyst 3850-48T",
      "serial_number": "ABC123DEF456",
      "platform": "ios",
      "primary_ip": "10.0.1.1",
      "site": "DC-East",
      "role": "access"
    },
    ...
  ],
  "page": 1,
  "page_size": 50,
  "total": 150,
  "has_next": true
}
```

**Error (404):**
```json
{
  "detail": "No NetBox snapshot found. Run discovery first."
}
```

**Data Path:** Snapshots table → SnapshotDevice records (source='netbox')

## Key Design Decisions

### 1. No New Database Tables
All endpoints query existing tables (snapshots, snapshot_devices, etc.). Zero schema changes.

### 2. No New Service Logic
Endpoints only expose what repositories already retrieve. No new comparison/discovery logic.

### 3. Pagination on List Endpoints
All list responses include page, page_size, total, has_next. Frontend can efficiently browse large inventories.

### 4. Optional Run ID in Device Comparison
`GET /devices/{id}/compare?run_id=X` compares against specific run; omitted = latest comparison.

### 5. Snapshot ID in All Responses
Frontend can trace results back to exact snapshot used. Enables audit trail + deep-dive.
